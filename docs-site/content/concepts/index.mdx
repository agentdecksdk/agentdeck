# Core Concepts

AgentDeck owns configuration; the OpenAI Agents SDK and LangGraph own execution. You write
four kinds of definition, and the platform supplies everything around them.

| You write | It is | Runs on |
|---|---|---|
| [Agent](/concepts/agents) | a class with instructions, tools, handoffs | OpenAI Agents SDK |
| [Capabilities](/concepts/capabilities) | a declaration of sandbox powers | SDK sandbox |
| [Skill](/concepts/skills) | a directory: `SKILL.md` + a script | subprocess in the sandbox |
| [Workflow](/concepts/workflows) | typed state + a graph | LangGraph |

## The shape of a project

Everything lives in `.agentdeck/` next to where you run. The path *is* the registration —
no catalog file, no `__init__.py`, no decorator to remember.

```text
.agentdeck/
├── agents/greeter/agent.py            # a BaseAgent subclass
├── workflows/new_booking/workflow.py  # a BaseWorkflow subclass
└── skills/parse-request/              # SKILL.md + scripts/run.py
```

`App` discovers, imports, builds, and compiles all of it, and fails fast if anything is
broken:

```python
import asyncio

from agentdeck import App


async def main() -> None:
    async with App.open() as app:
        print(app.load())  # {'agents': [...], 'workflows': [...], 'skills': [...]}


asyncio.run(main())
```

## What runs a turn

`App` is also the composition root: it wires the discovered project into one runtime and
hands it to whatever is serving. A chat — `App.chat`, or `POST /agents/{name}/chat` — is
played by that runtime, which records the turn as an event log: the run opening, text
deltas, tool calls, token usage per model call, then the result. The log is in memory by
default; point `AGENTDECK_EVENTS_BACKEND=sqlite` and `AGENTDECK_EVENTS_URL` at a file to
keep it across restarts.

## The division of labor

Deterministic code mutates external state; models decide. A model call never writes to
your systems directly — a node, a tool, or a skill does, and those are ordinary Python you
can test without a model.

Agents, workflows, and skills compose in any direction: an agent can be a workflow node
([`AgentNode`](/concepts/workflows)), a workflow can be an agent's tool
(`BaseWorkflow.as_tool()`), and a skill can be both a workflow node and an agent
capability.
