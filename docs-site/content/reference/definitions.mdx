# Definitions

Three classes are what a project actually subclasses. [Agents](/concepts/agents),
[Capabilities](/concepts/capabilities), and [Workflows](/concepts/workflows) cover why each
attribute exists and how they compose; this page is the exhaustive one — every class attribute
and every method, with its type and default.

## `BaseAgent`

```python
from agentdeck.agents import BaseAgent
```

| Attribute | Type | Default | Purpose |
|---|---|---|---|
| `name` | `str` | `""` | registry key and SDK agent name; falls back to the class name when empty |
| `instructions` | `str` | `""` | the system prompt |
| `handoff_description` | `str \| None` | `None` | how this agent describes itself to a peer deciding whether to hand off |
| `model` | `str \| None` | `None` | per-agent override; `None` uses the `OPENAI_MODEL` setting |
| `model_settings` | `Mapping[str, Any]` | `{}` | forwarded to `agents.ModelSettings(**model_settings)` |
| `tools` | `Sequence[Any]` | `()` | already-built SDK tools |
| `handoffs` | `Sequence[Any]` | `()` | peer agents this one can transfer to — a class, a registry name (`str`), a built `Agent`, or a `Handoff` |
| `output_type` | `type \| AgentOutputSchemaBase \| None` | `None` | a Pydantic model (or `AgentOutputSchema`) for structured output; `None` for free text |
| `hooks` | `AgentHooks \| None` | `None` | SDK lifecycle callbacks |
| `mcp_server_names` | `Sequence[str]` | `()` | names from the `mcp:` settings group this agent depends on |
| `subagents` | `Sequence[str]` | `()` | registry names spawnable via the `spawn_subagent` tool |

`build()` reads these into `Agent(**kwargs)`; an empty attribute drops out of the call so the SDK
applies its own default instead of an explicit empty one. Two methods matter beyond that:

| Method | Signature | Behavior |
|---|---|---|
| `build()` | `() -> agents.Agent` | builds a fresh SDK agent from the class attributes above — no caching across calls |
| `run()` | `(message=None, **runner_options) -> agents.RunResult` | one-shot **headless** run |
| `as_tool()` | `(**as_tool_kwargs) -> FunctionTool` | exposes this agent as a tool another agent can call |

`BaseAgent.run()` is not `App.run_agent()`. It builds the agent and calls the SDK's own
`Runner.run` directly — no Runtime, no event log, and it returns the SDK's `RunResult`, not a
`TurnResult`. Reach for it inside a script or a test that only needs one headless call and does
not care about the log; reach for `App.run_agent` (see [App](/reference/app)) for anything that
should be recorded and readable back afterwards.

An unknown name in `handoffs` raises `NotFoundError` naming the agents that do exist. MCP servers
named in `mcp_server_names` that are missing from config, or whose connection failed, are dropped
at build time rather than raised — an unreachable MCP host costs that agent its toolset, not the
whole process.

## `BaseSandboxAgent`

```python
from agentdeck.agents import BaseSandboxAgent, CapabilitiesSpec
```

Subclasses `BaseAgent` and adds one attribute:

| Attribute | Type | Default | Purpose |
|---|---|---|---|
| `capabilities` | `CapabilitiesSpec` | `CapabilitiesSpec()` | sandbox powers: shell, filesystem, memory, compaction, skills — see [Capabilities](/reference/capabilities) |

`build()` returns an `agents.sandbox.SandboxAgent` instead of a plain `Agent`, built from the same
`BaseAgent` attributes plus `capabilities.build(agent_model=cls.model)`. `run()` and `as_tool()`
are inherited unchanged.

## `BaseWorkflow`

```python
from agentdeck.workflows import BaseWorkflow, StateGraph, END
```

| Attribute | Type | Default | Purpose |
|---|---|---|---|
| `name` | `str` | `""` | registry key; falls back to the class name when empty |
| `description` | `str` | `""` | tool description when exposed via `as_tool()`; falls back to the class docstring's first line |
| `state` | `type` (a Pydantic model) | *required* | the graph's state schema — override on every subclass |
| `durable` | `bool` | `False` | compiles with a checkpointer (`AGENTDECK_CHECKPOINT_*`) when `True`, so a run can resume by `thread_id` after the process dies |

Override `build_graph()` — it must return an unbuilt `StateGraph` — and the rest is method-driven:

| Method | Signature | Behavior |
|---|---|---|
| `build_graph()` | `() -> StateGraph` | required override; the graph, uncompiled |
| `build()` | `() -> CompiledStateGraph` | compiles (and caches) the graph, with a checkpointer iff `durable` |
| `run()` | `(state=None, *, thread_id=None, **runner_options) -> Any` | runs the graph once; returns the final state or an `InterruptResult` |
| `run_stream()` | `(state=None, *, thread_id=None, **runner_options) -> AsyncIterator` | `node_update`/`custom` events, then `done` — or an `InterruptResult` in its place |
| `resume()` | `(thread_id, value, **runner_options) -> Any` | continues a paused run; `interrupt()` returns `value` |
| `pending()` | `() -> list[InterruptResult]` | every thread of this workflow currently paused on an interrupt |
| `as_tool()` | `(*, name=None, description=None, output_keys=None, defaults=None, strict_json_schema=False) -> FunctionTool` | exposes the workflow as a tool |
| `node_names()` | `() -> list[str]` | node names on the graph, excluding `START`/`END` |

`resume()` and a paused `interrupt()` both raise `ConfigError` when `durable` is `False` — there is
no checkpointer to resume from. `thread_id` is required when `durable` is `True` (a `ValueError`
otherwise) and ignored when it is not.

The same asymmetry as `BaseAgent.run()` applies here. Calling `SomeWorkflow.run(...)` directly
drives the compiled graph and writes nothing to the event log; `App.run_workflow` and
`App.resume_workflow` are what the Runtime actually plays, and record the run — see
[App](/reference/app). `App.run_workflow_stream` is the one App method that calls this class's own
`run_stream()` directly rather than through the Runtime, which is why it is also the one that
keeps no log of its own.

`as_tool()` requires `state` to be a Pydantic model (`TypeError` otherwise, since the tool's JSON
schema comes from `state.model_json_schema()`). `defaults` pins specific state fields to fixed
values regardless of what the model passes, and strips those fields from the schema the model
sees; `output_keys` filters the final state down to a subset of channels in the tool's return
value. Both are optional — the default is the whole schema, the whole final state.
