# Canonical Patterns

The project's taste, encoded as real good/bad pairs. An agent about to write code reads the pattern file for its concern and matches the good side. A new way of doing something a pattern already covers is a defect, not a style choice.

| Concern | File |
| --- | --- |
| Error messages | [errors.md](errors.md) |
| Comments | [comments.md](comments.md) |
| Run lifecycle | [lifecycle.md](lifecycle.md) |
| Tests | [tests.md](tests.md) |

A pattern earns a file here when review feedback recurs (deck-reviewer's promotion loop). One subject per file.
