# Rulings

Decisions taken while attacking the design, 2026-08-29. One row per question: what was chosen, what was rejected, why.

| # | question | ruling | rejected | why |
|---|---|---|---|---|
| 1 | how the gateway is realized | thin facade class in `agentdeck/bindings/gateway.py` wrapping `deck.runs`, adding `targets()`, `capabilities` and failure mapping | growing `Runs` itself; a `typing.Protocol` plus `deck.gateway` | `Runs` stays a user API, not an SPI; Deck grows no attribute; fakes can still satisfy the facade's interface |
| 2 | how failures reach a binding | one `GatewayError(code, message, cause)`; only `NOT_FOUND`, `BUSY`, `CONFLICT`, `INVALID_INPUT` carry a wire-safe message. `Run` methods keep their public errors; bindings map those directly | one exception class per code; result objects | one `except` per binding; result objects branch at every call site |
| 3 | `TargetInfo` fields in SPI v1 | `name`, `kind`, `description`, `input_schema` (`None` for free-text agents) | name and kind only; per-target capability flags | an A2A skill and an MCP tool need description and schema, and `Agent` already declares them; per-target flags are speculative until a target differs from its deck |
| 4 | `gateway.capabilities` | frozen dataclass with only what varies per deployment today: `control` (control signals cross processes; False on the default `memory://`, where control still reaches in-process runs) and `durable` (events survive restart and are readable across processes, so `from_seq` reconnect is honest) | seven bools; `frozenset[str]`; probing | A2A cards, ACP and MCP `initialize` advertise before a Run exists; the other five candidate flags are constant for every Deck, so they are decoration |
| 5 | how a binding picks the namespace | fixed per binding (`A2A.http(namespace="acme")`) or a callable on the request; default `None` | exposure-level auth hook; namespace carried on the wire; no namespaces over protocols | simple default with an escape hatch; the wire never carries a core identity; stdio has no request to hook |
| 6 | where authentication lives | in the protocol adapter, never in Deck or the gateway; `agentdeck/bindings/auth.py` offers one shared helper (`Principal`, credential verification) adapters may reuse, added with the first binding that calls it (#548 or #552), not in the SPI PR; each adapter extracts and advertises credentials its own way (AgentCard `securitySchemes`, MCP OAuth, none for stdio) | exposure-level middleware slot; per-binding hook wired into Deck; out of scope entirely | advertising and extraction are protocol vocabulary; verifying a token is not, so it is a util, not a Deck concern |
| 7 | external request ids as run keys | only where the protocol defines client-supplied, retry-safe ids: A2A `taskId` becomes `key`, so a retried send returns the existing task via `CONFLICT`; ACP, MCP and AG-UI ids never touch `key` | adapter-held id map; every id as key | `key` already does the dedupe; MCP call ids are per connection and would collide |
| 8 | external session concept | 1:1 onto `session_id`: A2A `contextId`, ACP session, AG-UI `threadId`, A2UI conversation; MCP has none unless the tool schema takes an optional `session_id` | adapter-generated ids with a map; prefixed ids | no adapter state; a shared id across protocols is the "one Deck, many projections" promise, and namespaces separate tenants |
| 9 | second message on a busy session | surface `BUSY`; each adapter renders it in its own vocabulary (409 with the holding run, A2A error, JSON-RPC error) | preempt by default; adapter-side queue | preempt would let an A2A peer kill someone's work; an adapter that wants preempt composes `cancel` then `start` from public calls |
| 10 | streaming client disconnects | the run continues and the client reconnects with `from_seq` (A2A `tasks/resubscribe` maps directly), unless the protocol's own client contract represents cancellation as aborting that transport, which AG-UI HTTP does (see 46) | cancel on disconnect everywhere; disconnect never cancels anywhere | deck-owned runs already survive their reader and a network blip must not cancel a task, but where a protocol's Stop button is literally an aborted request, honoring the abort is fidelity rather than a shortcut |

Principle behind 7 to 10: the Deck has one behavior; each adapter presents it in its protocol's terms and never asks the runtime to behave differently. A protocol that cannot be expressed through public calls is a missing gateway capability, not a reason to bend the runtime.
| 11 | presenting `run.interrupted` | each adapter maps it to its protocol's native "needs user action" mechanism and maps the reply back to `run.answer()`: A2A `INPUT_REQUIRED` with the question in the message, next client message resumes the task; ACP `request_permission` for approvals and its user-interaction mechanism for questions; AG-UI and A2UI interactive part or `requires-action` state; Native exposes `{run_id, interrupt_id, reason, payload}` plus an `answer` operation; a binding that does not advertise `hitl` refuses targets with `UNSUPPORTED` at start rather than stalling its client (ruling 26) | park the run and answer over Native only; adapter auto-refuses | a universal AgentDeck HITL wire shape would leak core onto every protocol; a silent stall or a machine-made refusal hides a decision from the user |
| 12 | event kinds a binding does not project | a binding declares a closed set of projected kinds; unmapped kinds and `UnknownEvent` are skipped with no per-event warning; at build time the binding validates that the required semantic categories (terminal state, text output, interruption if HITL is advertised) are covered and fails construction otherwise; contract tests prove the required kinds map | forward unknowns as generic metadata; warn per event | forward compatible without leaking the schema; a missing required projection is a configuration error, not a runtime surprise |
| 13 | content AgentDeck cannot represent | reject the whole request with `INVALID_INPUT` naming the part and listing supported kinds; nothing starts | start with the representable parts; convert to a URI reference | the caller must never believe the model saw something it did not |
| 14 | delivering artifacts | protocols v1 is reference-only: `artifact.created` stays `{artifact_id, media_type, uri, size}`; a binding projects that reference into its protocol-native artifact or resource type, or skips it if the protocol has none; it never implies AgentDeck can fetch, store, delete or proxy the bytes; the uri is owned by whoever produced the artifact; the gateway stays limited to targets, runs, events, control and HITL; an `ArtifactStorePort`, `ctx.artifacts`, retrieval and deletion are a separate future Artifacts epic that adds optional gateway capabilities without touching the SPI | artifact store inside the protocols epic; fetch via the Native endpoint; inline bytes | the store grows into an epic of its own (port, adapters, producer API, retention) and would stall protocols; a reference on the wire is exactly what the event already says |
| 15 | where bindings ship | in tree under `adapters/bindings/<name>/` as optional extras (`agentdeck[a2a]`, `agentdeck[acp]`, `agentdeck[agui]`, `agentdeck[a2ui]`, `agentdeck[mcp-server]`); the out-of-tree contract is proven by a test plugin under `tests/`, not by shipping separately | separate packages per protocol; hard dependencies | one repo, one CI, one release; five release trains would skew from day one; the SPI is still proven by the test plugin's import-linter contract |
| 16 | wire models | the official SDK where one exists (`a2a-sdk`, `agent-client-protocol`, `ag-ui-protocol`, `mcp`), each confined to its adapter by import-linter | hand-rolled pydantic models; SDK types with our own transport | spec drift is the SDK's problem; a second server loop doubles the surface to test |
| 17 | what the MCP server exposes | one MCP tool per target (`TargetInfo.name`, `description`, `input_schema`); `tools/call` starts a run, streams `report` and `text.delta` as MCP progress notifications, returns the final output; `run.interrupted` maps to MCP elicitation; runs are MCP resources; artifacts are projected as references (ruling 14) | generic `start_run`/`get_run`/`answer` tools; one tool per target without streaming or HITL | target-shaped tools are what an MCP client expects; long agent runs need progress or they hit client timeouts |
| 18 | "our own protocol" | Native is the AgentDeck protocol: `Native.http()` gets a versioned wire spec (canonical events on SSE, run, answer and artifact routes) and a `@agentdeck/client` JS package; no second protocol | a separate stdio or WebSocket AgentDeck transport; defer | canonical events already are the wire; a second transport waits for a non-HTTP embedder to exist |
| 19 | enforcing "no private imports" | an import-linter contract: `adapters/bindings/*` may import only `agentdeck.bindings`, `agentdeck.core.events`, `agentdeck.core.content` and public errors; plus a fixture plugin package under `tests/` that builds a binding with the same restriction, proving an outsider can | import-linter alone; review alone | the linter catches violations, the fixture proves the public surface is sufficient |
| 20 | protocol discovery | explicit in code (`deck.serve(A2A.http(), ...)`) until the SPI freezes; `.agentdeck/bindings` config and CLI flags arrive in Phase 6 and map 1:1 onto the factories | entry-point auto-mounting; CLI flags only | a network surface is never mounted by a `pip install`; flags cannot carry namespace or auth options |
| 21 | stdio and HTTP in one exposure | allowed; at most one stdio binding per process, HTTP bindings share one listener with unique paths; validated at `expose()` | stdio-only exposures; multiple stdio bindings | an IDE over stdio and peers over HTTP from one process is a real deployment; two protocols on one stdin has no framing |
| 22 | release shape | superseded by 37: v6.0.0 ships the SPI, Native, A2A, WhatsApp and Terminal; the SPI freezes only once an HTTP/chat protocol and a task or stdio protocol both work; the remaining bindings ship as 6.x minors | all six in 6.0; SPI plus Native only | freezing on HTTP-only evidence is what the roadmap warns against; six bindings in one release is too long |
| 23 | `deck.expose` vs `deck.serve` | (amended: #606, #623) `serve()` and `asgi()` on `Deck` are the primary API; `serve()` is synchronous and blocking (`asyncio.run` over `serve_async()`, owning the event loop), `serve_async()` is its async form for a caller already inside one, and `asgi()` is unchanged. All three are exactly `expose(*bindings).serve()` / `.asgi()`; `expose()` is the lower-level call, returning the `Exposure` object itself for callers who need it | `deck.serve(*bindings)` sugar now (originally rejected, #549); a third verb; folding `expose()` away entirely; an async-only `serve()` (#623) | the one-line saving #549 rejected is now the documented happy path, since every doc taught it anyway; the common case is a process whose only job is to serve, which should not need `asyncio.run` |
| 24 | what a binding must translate | the gateway exposes the smallest common execution capabilities; a binding translates only the subset its protocol can faithfully represent and never changes runtime semantics to ease the translation | "every protocol maps the same five things" | MCP's primary abstractions are tools and resources, not runs with cancel buttons; forcing uniformity would distort the SPI toward chat |
| 25 | external identity rule | conversation identity maps to `session_id` when semantically a conversation; request or task identity is an adapter-local mapping to the Run address; a retry or idempotency id maps to `key` only when the protocol defines retry semantics; no id casually becomes both | `contextId`, `threadId`, `taskId` all "map onto `session_id` and `key`" | they mean different things; an A2A `taskId` is a task, not a conversation and not automatically idempotent |
| 26 | required projections | superseded by 40 for the check's location: a binding advertises what it supports (`streaming`, `text`, `hitl`, `control.cancel`, ...); `expose()` validates that every advertised capability has its projection or action implemented; unadvertised canonical kinds may be skipped; advertise it, implement it | three hardcoded mandatory kinds (terminal, text, interrupt) | a tools-only or fire-and-forget binding is legitimate; ruling 12's build-time check is kept, its fixed list is replaced by the advertisement |
| 27 | when the gateway grows | if a capability is part of AgentDeck's execution model and unreachable through the gateway, the gateway is incomplete and grows; if it is protocol-specific (Slack channels, A2A push subscriptions, MCP roots) it stays in the binding | "if you cannot do it through the gateway, that is our bug" | without the qualification every plugin author can justify growing the gateway with their protocol's nouns |
| 28 | reconnect and auth wording | `Event.seq` is the common replay primitive from which each binding implements its protocol's reconnect, possibly with adapter-owned cursor or task state; wire authentication mechanics belong to the binding, authorization policy may belong to the deployment and is passed in, the runtime stays ignorant of both | "reconnect for free"; "auth is protocol vocabulary" | some protocols need more than a seq cursor; adapters must not each own policy |
| 29 | following a run across suspension | segment follow is the contract: `Run.events(follow=True)` stops at a terminal event or a suspension (`deck.py` `Run.events`), and a binding tails one segment per interaction, re-tailing from `last_seq + 1` after anyone drives `answer()` or `resume()`; a re-tail started while the run is suspended blocks until the resumed segment writes, so nothing polls on a timer; every protocol's HITL boundary is already a stream boundary (A2A `input-required` ends the stream, AG-UI `RUN_FINISHED`, a channel's webhook, a terminal prompt); the fixture pins "re-tail after a suspension" as a contract test; no runtime change | `through="suspensions"` on `Run.events`; `gateway.watch_run()`; removing the boundary | nobody holds one stream across a human decision, and the wait is already built in; zero runtime changes for the epic |
| 30 | observers and protocols | bindings never register `Observer`s; they tail runs through the gateway. Observers are deck-wide, fire-and-forget, lossy taps for telemetry; a protocol needs per-run, per-client, replayable streams with reconnect, which only the store gives. A push-style protocol (A2A push notifications, webhooks) that needs "tell me when any run changes state" is an execution-model capability and grows the gateway (a run-lifecycle subscription), not an observer registration on the Deck | bindings register an observer for fan-out | an observer can lose events by contract and sees every run in the deck; registering one would couple the binding to `Deck`, the exact SPI widening ruling 1 avoids |
| 31 | protocols vs channels | one `Binding` contract (`info`, `build(gateway) -> Endpoint`) with `BindingInfo.kind: "protocol" \| "channel" \| "surface"`; a protocol is a machine-facing interoperability contract (A2A, ACP, MCP, AG-UI), a channel is an existing communication network with its own messaging identity and API (Slack, WhatsApp, Telegram, Discord), a surface is a user-facing interface someone uses to interact with the Deck (CLI, TUI, web app, desktop app); both project the same Deck through the same gateway; a channel typically advertises `streaming=false` and projects `message.completed`, with buttons from `run.interrupted`; channel ids and bot credentials are binding-owned; a binding may choose any opaque `session_id` string, including a channel prefix, since ruling 8 only rejected making prefixes a requirement; WhatsApp is the reference channel inside the v6 epic (ruling 37), other channels follow | three ABCs (`ProtocolBinding`, `ChannelBinding`, `SurfaceBinding`) | identical interface, one type; the taxonomy is semantics and packaging, so it is data, not hierarchy |
| 32 | binding background work | `Binding` gains `start()` and `stop()` hooks; the Exposure owns every binding's lifecycle (started in order after the gateway exists, stopped in reverse on shutdown, included in the atomic-startup rollback) and each binding owns the tasks it spawns, draining them in its own `stop()`: a per-message tail cannot be started at `start()` time, since no Run exists yet | passive `Endpoint` only; bindings spawn unowned tasks | a channel must ACK a webhook and keep tailing the run afterwards; an unowned task survives a failed startup or leaks on close |
| 33 | the fixture plugin's shape | the out-of-tree fixture plugin under `tests/` (ruling 19) is channel-shaped: ack-then-continue, no streaming, durable external-id to run map across restart | a request-response HTTP fixture | proves the SPI is not biased toward request-response HTTP, the concern behind Phase 4, before any real channel exists |
| 34 | fate of `surfaces/` | deleted in Phase 2 together with `agentdeck/serve.py`, the `agentdeck-serve` script and the ring-3 import-linter contracts naming `agentdeck.surfaces`; `agentdeck chat` becomes the `Terminal.stdio()` surface (ruling 35); `agentdeck serve` becomes CLI flags over `deck.serve(...)` in Phase 6; `engineering/architecture.md` replaces the `surfaces/` ownership row with `adapters/bindings/` | keep `surfaces/` for the CLI | after ruling 3 it would hold only `cli/chat.py`, a client of the deleted v1 wire; the CLI entry point already lives in `agentdeck/cli.py`; "protocol ingress" is what `adapters/bindings/` now owns |
| 35 | the CLI is a surface | `agentdeck chat` is `Terminal.stdio()`, a `kind="surface"` binding over `StdioEndpoint` on an in-process Deck: reads lines, `gateway.start`, renders `text.delta` live, numbered prompt for `run.interrupted`, one session per process; no auth, no store, no background task; ships in Phase 2 next to Native and replaces `surfaces/cli/chat.py`; a remote `agentdeck chat --url` over the Native wire is Phase 6 | a Native-wire client only | Slack, WhatsApp and a terminal differ only in transport and rendering limits, the contract is identical; the terminal is the simplest surface, so it exercises the binding contract and `StdioEndpoint` with no platform noise, before ACP needs stdio in Phase 4 |
| 36 | package names after the taxonomy | the SPI package is `agentdeck/bindings/` and in-tree bindings live in `adapters/bindings/<name>/`, one folder for all three kinds; `agentdeck.bindings` is not created | `agentdeck/bindings/` plus `adapters/bindings/` | a folder named protocols holding Slack and a terminal misleads; one folder, kind is data |
| 37 | the v6.0 reference trio | v6.0.0 ships one binding of each kind over one Deck: `A2A.http()` (protocol), `WhatsApp.http()` (channel), `Terminal.stdio()` (surface), plus Native and the SPI; `deck.serve(A2A.http(), WhatsApp.http(), Terminal.stdio())` is the canonical example and the cross-kind contract test; AG-UI, A2UI, ACP and the MCP server follow as 6.x minors in the order agreed in rulings 2 and 17; amends 22 (release) and 31 (channels were outside the epic) | AG-UI or A2A alone first; channels deferred entirely | one of each kind is the only evidence that the taxonomy and the SPI hold; a webhook channel forces the ACK-then-continue lifecycle (ruling 32) into the freeze evidence, exactly what Phase 4 wanted from a structurally different protocol |
| 38 | external surfaces | an external surface (Assistant UI, a custom React app, an IDE, another agent) is a client of a protocol binding, never a binding of its own: Assistant UI consumes AG-UI via `@assistant-ui/react-ag-ui` or A2A via `@assistant-ui/react-a2a`, an IDE consumes ACP, an agent consumes A2A; `kind="surface"` is reserved for surfaces AgentDeck hosts in-process (Terminal, a TUI); no `AssistantUIBinding` is ever written; in v6.0 the web UI for the trio is Assistant UI over `A2A.http()` with zero AgentDeck code | an `AssistantUI.http()` binding (the original design's Phase 3) | AgentDeck does not need to know Assistant UI exists; implement the protocol once and every compatible surface works, which is the design's own success test |
| 39 | an in-house web chat | `WebChat.http()` is a `kind="surface"` binding that serves a stock Assistant UI build over `HttpEndpoint` and points its AG-UI runtime at an `AGUI.http()` binding in the same exposure; it depends on that binding's public wire only, and `expose()` validation may require a binding's declared prerequisites to be present; end state after AG-UI ships in 6.x, needs a JS build step decision; no `AssistantUIBinding` (ruling 38 holds) | a bespoke web UI binding with its own wire | the browser analogue of `Terminal.stdio()`; composing over a protocol binding's wire keeps one UI protocol and proves the surface kind covers hosted web apps |
| 40 | where an advertisement is checked | the SPI contract suite holds a binding to every name in `BindingInfo.advertises`; `expose()` checks only what it can know without running the binding (spi_version, paths, stdio count, names, `requires`) | a `BindingInfo.projects` set that `expose()` compares against `advertises` (amends 26) | both sets are declared by the same binding, so the comparison proves nothing a broken binding cannot satisfy by declaring both; it is permanent SPI surface for a tautology |
| 41 | a second instance of one binding | a factory defaults `BindingInfo.name` to its protocol, channel or surface name and takes `name=` for a second instance in the same exposure (`Native.http(path="/other", name="native-elsewhere")`) | deriving the name from `path` or `namespace` | `name` is lifecycle and `requires` identity, not routing identity: deriving it from a route makes two deployments of one binding rename themselves whenever a path changes, and `expose()` rejects a repeated name (#546) |
| 42 | what an AG-UI endpoint serves | one `AGUI.http()` serves the whole Deck: any agent or workflow in the catalog is reachable through it, and `target=` pins one endpoint as convenience | one endpoint per agent, the shape every AG-UI example shows | a Deck is the unit AgentDeck runs, and per-target endpoints multiply routes, names and auth surfaces for nothing; the pinned form still exists for a single-purpose deployment |
| 43 | how a client names a target | an explicit `forwardedProps.agentdeck.target`, and a pinned binding rejects a request naming a different one | overloading `threadId` or `runId`; a header; a path segment | both ids already mean something in AG-UI, and silently overriding a pinned target hides a routing bug from the caller |
| 44 | AG-UI `runId` and `Run.id` | different identities: `runId` is the protocol interaction, `Run.id` the execution, and one Run spans several interactions across suspension and resume | `runId == Run.id`, the obvious mapping | HITL makes them diverge on the first `ctx.ask`, and a client that assumed equality would lose the run it was resuming |
| 45 | AG-UI conversation history | the transcript is protocol context and only the new message becomes input; branching, editing and regeneration are unsupported until they are designed | replaying the transcript into the Deck each turn | the session already owns the conversation, so replaying it duplicates history, and guessing at branch semantics writes a bug into the wire |
| 46 | a disconnected AG-UI client | request cancellation or disconnect means `Run.cancel()`, because AG-UI's `HttpAgent.abortRun()` is represented by aborting the request; an AG-UI HTTP transport rule, not the default Run-reader behavior (amends 10) | disconnect never cancels; a grace period | it is what the official client's Stop button does, and scoping it to the transport is what lets a resumable AG-UI transport choose otherwise without re-litigating |
| 47 | unsupported stable AG-UI features | each is a tracked gap naming the generic AgentDeck primitive it needs (run-scoped tools, shared state, mid-run input, `run.answer(interrupt_id, value)`, tool-output streaming), and the binding refuses them explicitly | implementing them inside the binding; calling the subset the protocol | `AGUI.http()` is a compatibility claim, and a protocol-shaped workaround in a binding is what `invariants.md` exists to prevent |
| 48 | the AG-UI binding's internal shape | transport plus adapter, two modules in the AG-UI binding package (`binding.py`, `adapter.py`), the adapter translating both directions; no shared base class, and no other binding is held to the same layout until one needs it | a `projector.py` naming a new concept; a generic `ProtocolAdapter` extracted up front; the same file shape mandated for every binding | AG-UI has substantial bidirectional translation and more than one plausible transport, which is what earns the split, while Native and Terminal do not; `adapters/` stays the implementation layer and only the module inside a binding is called an adapter |
| 49 | how generic an AG-UI endpoint is | `AGUI.http(target="Support")` is plain AG-UI interoperability and a client needs only the URL, while `AGUI.http()` serves the whole Deck through the optional AgentDeck extension `forwardedProps.agentdeck.target`, which the client has to know about; resolution is deterministic down to a 4xx naming the available targets | claiming both modes are equally generic; inventing an AG-UI target-discovery extension | `forwardedProps` is opaque application data AG-UI itself never consumes, so a generic client cannot discover targets, and AG-UI defines no discovery vocabulary for a binding to borrow |
| 50 | what `RUN_STARTED` and `RUN_FINISHED` describe | the AG-UI interaction, not the lifetime of the canonical Run: the binding emits `RUN_STARTED` once per incoming `RunAgentInput` using that request's `threadId` and `runId`, the adapter closes the envelope from the segment's terminal event, and `run.started` is therefore not projected | projecting `run.started` to `RUN_STARTED` | a resume continues the same Run and produces `run.resumed`, never a second `run.started`, so a projected envelope would leave the resumed interaction without the `RUN_STARTED` the protocol requires |
| 51 | AG-UI as protocol or as transport | AG-UI is the protocol and `AGUI.http()` is its first transport: `adapter.py` owns protocol translation, `binding.py` owns HTTP/SSE lifecycle, and a later persistent transport reuses the adapter with its own disconnect and reconnect semantics | treating AG-UI as synonymous with HTTP/SSE | the split is what makes a second transport a new `binding.py` instead of a rewrite, and it is why the disconnect rule is scoped to the transport (46) |
| 52 | unsupported `RunAgentInput` fields | every standard field the binding cannot honor is a tracked gap naming its AgentDeck primitive, `parentRunId` and branch, edit or regenerate on run branching and non-empty `context` on a generic run-scoped semantic context, and each is refused with a reason rather than ignored | ignoring a field the binding does not implement; listing only tools, state, interrupts and steering as the gaps (amends 47) | `context` carries semantic run context that AG-UI integrations rely on, so dropping it silently makes the endpoint quietly wrong instead of honestly incomplete |
